# ISM Digital Museum

Мэдээллийн Системийн Менежментийн тэнхимийн түүх, багш нар, арга хэмжээ, оюутны бүтээл, технологийн хөгжлийг нэг дор хадгалж, интерактив хэлбэрээр танилцуулах веб аппликейшн. Интернет програмчлалын гэрийн даалгавар №1.

> **Анхаарах:** `supabase/seed.sql` дахь нэр, огноо, түүх, зураг нь зохиомол жишээ өгөгдөл. Сайтын хөл хэсэгт ч үүнийг тэмдэглэсэн. Тэнхимийн бодит мэдээллийг зөвшөөрөл авсны дараа админ хэсгээр оруулна.

### Хэрэглэгчийн төрөл

- **Зочин:** нийтлэгдсэн агуулгыг үзэж, хайна.
- **Бүтээгч / оюутан:** өөрийн бүтээлээ нэмж, засаж, устгана. Бүтээл админы хяналтын дараа нийтлэгдэнэ.
- **Администратор:** нийтэд харагдах бүх агуулгыг хянана.

## Технологи

- **Frontend:** React 19, JavaScript, React Router, Vite, цэвэр CSS
- **Backend:** Supabase (Authentication, PostgreSQL, Storage, Row Level Security)
- **Байршуулалт:** GitHub, Vercel

## Суулгах заавар

Шаардлага: Node.js 20+, Supabase-ийн үнэгүй бүртгэл.

```bash
git clone <repository-url>
cd ism-digital-museum
npm install
```

1. [supabase.com](https://supabase.com) дээр шинэ төсөл үүсгэнэ.
2. **SQL Editor** дээр дарааллаар нь ажиллуулна:
   - [`supabase/migrations/0001_schema.sql`](supabase/migrations/0001_schema.sql): хүснэгт, RLS, Storage
   - [`supabase/seed.sql`](supabase/seed.sql): жишээ өгөгдөл (заавал биш)
3. `.env.example`-г `.env` нэрээр хуулж, **Project Settings > API** хэсгийн Project URL болон нийтийн (anon) түлхүүрийг бичнэ. `service_role` түлхүүрийг хэзээ ч бүү ашигла.
4. Ажиллуулна:

```bash
npm run dev
```

### Админ эрх олгох

Сайтаар бүртгүүлсний дараа SQL Editor дээр:

```sql
update public.profiles set role = 'admin'
where id = (select id from auth.users where email = 'таны@имэйл');
```

`role` баганыг API-аар өөрчлөх эрх хэрэглэгчид байхгүй тул зөвхөн ингэж олгоно.

### Vercel-д байршуулах

Repository-г Vercel-д импортолж, Environment Variables хэсэгт `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`-г нэмнэ. Build тохиргоог `vercel.json` зааж өгсөн.

Supabase-ийн **Authentication > URL Configuration** хэсэгт Site URL-ийг Vercel домайнаар солино. Ингэснээр баталгаажуулах холбоос зөв хаяг руу очно.

## Аюулгүй байдал

- Бүх хүснэгтэд **RLS** идэвхтэй. Хэрэглэгч зөвхөн өөрийн өгөгдлийг өөрчилнө, тэнхимийн агуулгыг зөвхөн админ өөрчилнө.
- `role` баганад `UPDATE` эрх олгоогүй тул хэрэглэгч өөрийгөө админ болгож чадахгүй.
- `exhibits_guard` триггер нь админ бус хэрэглэгчийн бүтээлийг `pending` төлөвт оруулж, эзэмшигчийг солихоос хамгаална.
- Storage-д хэрэглэгч зөвхөн өөрийн `<user id>/` хавтаст бичнэ. 5 MB-аас их файл, SVG-г хүлээж авахгүй.
- `demo_url`, `github_url` нь зөвхөн `http(s)` байна, `javascript:` холбоог өгөгдлийн сан татгалзана.
- Frontend зөвхөн нийтийн түлхүүр ашиглана, `.env` нь git-д орохгүй.

## Тест

```bash
npm test
```

- `tests/rls.test.js`: миграцийг локал PostgreSQL (PGlite) дээр ажиллуулж, зочин, бүтээгч, админы эрхээр RLS-ийг шалгана. Supabase-ийн `auth`, `storage` схемийг stub орлодог тул эцсийн шалгалтыг бодит төсөл дээр давтана.
- `tests/filter.test.js`, `tests/timeline.test.js`: хайлт, Time Machine-ийн логик.

## Кодын бүтэц

```
src/
  lib/          Supabase клиент, өгөгдлийн функц, хайлт, timeline-ийн логик
  context/      Нэвтрэлтийн төлөв (AuthContext)
  hooks/        useLoad: ачаалах, алдаа, хоосон төлөв
  components/   Дахин ашиглагдах UI (ExhibitCard, ImageUpload, CrudSection...)
  pages/        Чиглүүлэлтийн хуудсууд
supabase/       Схем, RLS, жишээ өгөгдөл
tests/          RLS болон логикийн тест
```
